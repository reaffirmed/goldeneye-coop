Fixes release of GoldenEye 007 story co-op, built on Project Midas 1.0.2b.

**Works with v0.7.0.** The co-op protocol version stays at 17, so v0.7.1 players can play with anyone on v0.7.0. Players on v0.6.15 or older can't play with v0.7.0 or later and must update. Players on v0.6.13 to v0.7.0 are asked to update by the game; players on v0.6.12 back to v0.3.0 get the update from the top of the CO-OP screen's PLAY tab ("Update to v0.7.1 - Install", or pick **Check Now** on the CONTROLS tab). Players on v0.2.1 or older have no updater and need this zip from GitHub (`GoldenEye-Coop-v0.7.1-win32.zip`). Every player needs their own GoldenEye 007 (USA) cart image in the `Data` folder; the image is not included. See `README-COOP.txt` inside the zip. The Surface 2 and body fixes work when the host is on v0.7.1; the Streets fix works for each joiner on v0.7.1.

## Updates

- **The update offer comes when you open the game.** From v0.7.1 on, a new version is offered in a box before the game window opens, not later on the Files screen. The game waits up to 3 seconds for GitHub; if it doesn't answer, the game starts as normal and the CO-OP screen offers the update later. The box gives both versions and the download size, and has the same three answers as before: **Update Now**, **Not Now** (asks again next time) and **Skip This Version**. Update Now shows a progress window, then starts the new version. Closing that window starts the game while the download finishes in the background. If a download fails, the box says why and offers **Try Again** or **Play Now**, and nothing in the folder changes. Your saves, settings and cart image are never touched. With `auto_update=0` in `midas.ini` nothing is asked. This release is the first to ask this way, so v0.7.0 players still see the old prompt for it.

## Story co-op

- **Surface 2: no phantom guards after the alarm.** With the alarm on and nobody near the reinforcements' spot, the level keeps making guards that remove themselves at once. The joiner showed one to three of them standing there that the host never had, and the joiner's guards drifted out of step with the host's. The host now sends a new guard only once it has stayed for a moment, so guards that vanish at once never reach joiners.
- **Streets: no false "too many civilian casualties" on the joiner.** In some games, only the joiner saw "Warning: Civilian casualties high", then "critical", then "Mission Failure: Too many civilian casualties", and their mission state fought the host's. The joiner's copy of the casualty count only ever went down. The count is now left to the host, and its captions still reach every player. Archives uses the same commands; there the guards' state now comes from the host too.
- **Bodies fade on every screen.** When the host ran slowly (under about 40 frames a second), a joiner could miss a body's fade: it stood until the host removed it, then vanished. The host now sends a fading body in each of the first snapshots of its fade.

## Behind the scenes

The co-op test checklist was re-recorded on v0.7.0's code, with new automatic checks for Facility, Silo, Streets, Surface 2 and Train. It found the Surface 2 and Streets bugs above.

## Known issues

- The new update box and its progress window were tested on Linux, not yet on real Windows. If the box doesn't show, the CO-OP screen still offers the update.
- Bunker 2: at the end of the escape, a joiner can see a cutscene without Natalya, or have their mission end as the host's cutscene starts. A fix is being tested.
- The fix for a game splitting in two after a long dropout has been tested on our simulated network, not yet in many real Steam games. If you still end up in two separate games after a dropout, an F8 report from both players helps.
- The crash-safe saves and the updater's resume were tested on Linux. Their Windows-only parts haven't had a run on real Windows yet.
- In Bunker 2 a joiner's punches have been reported missing the cell guard; we haven't reproduced it yet. F8 reports help.
- The game still keeps its saves and updates in its own folder, so it needs a folder you can write to (not Program Files).
