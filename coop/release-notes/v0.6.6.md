Guard animation fix release of GoldenEye 007 story co-op, built on Project Midas 1.0.2b.

**Everyone must update: v0.6.6 does not play with v0.6.5 or older.** The co-op protocol version goes from 14 to 15 (the host now sends where each guard's idle animation loops), so a v0.6.5 player can't join a v0.6.6 host or the other way round. Players on v0.6.5 back to v0.3.0 get the update from the game itself: the top of the CO-OP screen's PLAY tab shows "Update to v0.6.6 - Install" (or pick **Check Now** on the CONTROLS tab), and trying to join a v0.6.6 host offers it at once. Players on v0.2.1 or older have no updater and need this zip from GitHub. Every player needs their own GoldenEye 007 (USA) cart image in the `Data` folder; the image is not included. See `README-COOP.txt` inside the zip.

## Fixed

- **Patrolling guards animate smoothly on the joiner.** On any level, a patrolling guard the host couldn't see stood frozen on the joiner and only jumped forward each time an update came from the host, so its walk and crouch-to-shoot looked like they skipped steps (Dam's tower guard was the clearest case). Every guard the host controls now plays its animation every frame on the joiner.
- **Far-off standing guards keep moving while a partner watches.** The host stopped animating a standing guard that nobody on its own screen could see, even when a partner far away was looking right at it. The host now keeps standing guards animating while a partner is playing.
- **Idle guards no longer snap back.** A guard's idle animation loops before its last frame, and the joiner didn't know where, so it played past the loop and jumped back each time round. The host now sends the loop point.

## Known issues

- The game still keeps its saves and updates in its own folder, so it needs a folder you can write to (not Program Files).
