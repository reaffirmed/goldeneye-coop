Netcode and reliability release of GoldenEye 007 story co-op, built on Project Midas 1.0.2b.

**Everyone must update: v0.7.0 does not play with v0.6.15 or older.** The co-op protocol version goes from 16 to 17 (the fix for a game splitting in two after a long dropout needs it), so a v0.6.x player can't join a v0.7.0 host or the other way round, in co-op or versus. Either side gets a "Different Versions" message if they try. Players on v0.6.13 to v0.6.15 are asked to update when the game opens; players on v0.6.12 back to v0.3.0 get the update from the top of the CO-OP screen's PLAY tab ("Update to v0.7.0 - Install", or pick **Check Now** on the CONTROLS tab). Players on v0.2.1 or older have no updater and need this zip from GitHub (`GoldenEye-Coop-v0.7.0-win32.zip`). Every player needs their own GoldenEye 007 (USA) cart image in the `Data` folder; the image is not included. See `README-COOP.txt` inside the zip.

## Story co-op

- **A long dropout no longer splits the game in two.** If a joiner's connection went quiet for more than a few seconds while the host was still playing, the joiner took over as host. When the connection came back, there were two games running side by side that never joined up again. Now the two sides keep calling each other for up to a minute after a dropout, and when they meet they settle on one host: whoever owns the Steam lobby keeps the game. The other player's mission ends back to the lobby for a moment, and they rejoin the running mission like any late joiner. With 3 or 4 players, anyone who followed the wrong host is sent to the right one too.
- **Important events survive a busy connection.** When a lot happens at once (big fights, explosions), a joiner's queue of events from the host could fill up and lose some. The last places in the queue are now kept for the events that can't be mended later: mission end, objectives, cutscenes, endings and script orders. Anything else that is lost is mended by sending the joiner a fresh copy of the world once things calm down.
- **No crash when taking over from a guard's death.** A joiner who took over as host just as a guard was dying on their screen could crash. Fixed.
- **Statue: Valentin's meeting no longer fails on a hiccup.** If the joiner was talking to Valentin and their connection stalled for 3 seconds or more while the host stood far away, the host's game decided Bond had walked off and failed objective A, while the joiner's showed it complete. A partner whose connection goes quiet now still counts as standing where they were last seen. The same goes for the Janus meeting.
- **Jungle: killing Xenia credits the right player.** When a joiner killed Xenia, the toast, the results screen and the stats all gave objective B to the host. They now credit whoever did the damage.
- **Aztec: the shuttle countdown runs when a joiner launches it.** If a joiner uploaded the launch data, the 30-second launch countdown was skipped on both screens and the objective completed at once. The joiner's game now waits for the host's clock, so the countdown runs on every screen as it does in solo. The same wait covers the other mission countdowns.
- **Joiners' aircraft and guard checks.** On a joiner's screen, planes and helicopters that copy the host's flight could start their animation at the wrong frame and speed. The host's check for whether a guard is on a partner's screen also used a wrong angle for the partner's facing. Both now get the right numbers.
- **Safer against bad packets.** A player in the game, or anyone who could reach it over the network, could send packets that ended the mission for everyone, marked players as gone, hurt the host as if they were a guard, or crashed the host or other joiners. The host now refuses everything only it may send, and every game checks the sizes, positions and numbers in what it receives. Late packets from an earlier session are ignored instead of restarting the connection, and after 5 wrong lobby passwords from one player the host stops answering them for 30 seconds.

## Saves and updates

- **Saves and settings are never left half-written.** Your saves (`eeprom.bin`), settings (`midas.ini`), key binds, profiles, versus stats, weapon sets and match settings were rewritten in place. A crash, a forced quit, a power cut or a full disk at the wrong moment could leave the file empty, which for `eeprom.bin` meant every solo folder's progress at once. Each file is now written whole to a temporary copy and only then swapped in, so the old file stays if anything goes wrong. The backup a new build takes of `Data/Saves` is also all or nothing now.
- **An update cut off half way finishes on the next start.** If the game was closed, crashed or lost power while the updater was moving the new files in, the folder could be left part old, part new, with a file missing, and nothing noticed. The updater now keeps a list of what it is moving and finishes the job when the game next opens.

## First start and error messages

- **The missing-cart message says what it found.** When no usable cart image is found, the message now lists each file it refused and why: the Europe (PAL) or Japan version ("This game needs the USA cart"), a modded or patched USA image, a cut-short download, or another N64 game. A ROM path you set that doesn't exist is named in full.
- **A read-only folder warns about everything you'd lose.** Installed somewhere the game can't write to (Program Files, or with Controlled Folder Access on), the warning now says that settings, mission progress, the co-op campaign and profiles won't be kept and updates can't install, not just settings.
- **The CO-OP screen says why Steam is off.** Instead of always "Steam is not running", it now tells you when the game's `steam_api.dll` is missing or damaged (unzip the game again; some virus scanners remove it) and when Steam turned the game away (check you're logged in and online).

## Behind the scenes

Every co-op change is now checked by more automatic tests: mission runs that can't quietly pass when skipped, a memory-safety build, tests for the save and updater fixes, a guard against new compiler warnings, and a build that never downloads a cart image.

## Known issues

- The fix for a game splitting in two after a long dropout has been tested on our simulated network, not yet in many real Steam games. If you still end up in two separate games after a dropout, an F8 report from both players helps.
- The crash-safe saves and the updater's resume were tested on Linux. Their Windows-only parts (flushing to disk, retrying when a virus scanner holds a file) haven't had a run on real Windows yet.
- In Bunker 2 a joiner's punches have been reported missing the cell guard; we haven't reproduced it yet. F8 reports help.
- The game still keeps its saves and updates in its own folder, so it needs a folder you can write to (not Program Files).
